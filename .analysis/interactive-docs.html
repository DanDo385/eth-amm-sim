Overview

A four-tier system for demonstrating and observing automated market-maker execution against a deterministic local chain.

eth-amm-sim is a multi-agent trading simulator plus a real-time observability SPA. It exists to produce a repeatable, watchable demo: start a session, watch ~21 bots trade a constant-product pool for two to three minutes, and see price, TWAP, liquidity-provider PnL, price impact, and a trade blotter update live.

The four tiers

TierStackRole
Anvil chain Foundry Anvil, chainId 31337 Deterministic local EVM with 30 funded accounts on port 8545.
Contracts Solidity ^0.8.20, OpenZeppelin AppleToken (ERC20) and AppleAMM (x·y=k, 30 bps fee), deployed and seeded by Deploy.s.sol.
Go backend Go 1.25, go-ethereum, gorilla/mux + gorilla/websocket Bot goroutines, ABI-encoded swap execution, 2s chain poll loop, metrics aggregation, REST + WebSocket fan-out on port 8080.
Frontend SPA Vite 5, React 18.3, TypeScript 5.8, Tailwind, lightweight-charts Live dashboard and per-account performance views; all data I/O confined to hooks.

Key structural takeaways

  • Clean layered Go backend; two errgroups own every goroutine (process-level and per-session bot pool) with graceful SIGINT/SIGTERM drain.
  • internal/config is the cross-language hub — the 30-account roster is re-derived independently in Go and in Deploy.s.sol with no shared schema.
  • Largest test gap: internal/bots/ (~850 LOC of strategy logic, 0 tests) and the entire frontend.
  • Two representations of the AMM ABI (hand-packed calldata in executor.go plus generated bindings) invite silent drift.
  • All state is in-memory and unbounded — fine for a 3-minute demo, a slow leak for an always-on staging instance.

Test evidence

Both suites passed during analysis: go test ./... (backend packages chain, config, engine, metrics, server) and forge test (22/22 for AppleAMM.t.sol and AppleToken.t.sol). The frontend has no test suite; bots, store, and cmd have no test files.

Coupling notes

  • config.Accounts is the single roster shared by Deploy.s.sol, main.go, Executor, /accounts, and the frontend.
  • store imports engine (stores engine.Trade); engine never imports store — the OnTrade closure in main.go inverts the dependency.
  • The store ↔ metrics cycle is broken by the metrics.PriceDataStore interface; bots get a read-only PriceProvider view.
  • The contract ABI exists twice: hand-packed in executor.go and generated in internal/contracts.
  • No database, auth, or queue — all state is in-memory and reset per session.

Critical Flows

Four execution paths that define the system. The first two are the demo's hot loop.

A · Session start (control plane)

Operator clicks "start" → bots spawn

  1. SPA SessionControls issues POST /session/start with a duration.
  2. handlers.handleSessionStart calls Session.Start(ctx, duration).
  3. Session transitions idle → running, arms its timer.
  4. Orchestrator.Start(ctx) spawns bot.Run for every non-LP / non-User account inside an errgroup.
  5. Status is broadcast over WS; the SPA re-renders.
  6. Timer expiry or POST /session/stop cancels ctx → all bots exit → StatusCompleted.

B · Bot / user trade → UI

A swap becomes pixels

  1. bot.Run loop (or POST /trade/{buy,sell}) decides to trade.
  2. Executor.SwapETHForApples / SwapApplesForETH: NonceManager.Next → sign tx → Anvil eth_sendRawTransaction.
  3. Executor reads LogSwap + constant-product math → builds an engine.Trade.
  4. OnTrade callback (registered in main.go:163) fires:
    • MemoryStore.RecordTrade
    • MemoryStore.RecordTradeFlow → notifies MeanRev bots (EWMA z-score)
    • MemoryStore.RecordEvent → large / critical trade thresholds
  5. server.BroadcastTrade / BroadcastEvent / BroadcastAccountUpdate (up to 3 frames).
  6. WS /stream fan-out → SPA handleWSMessage → Blotter / KeyEvents / AccountMetrics / PriceChart re-render.

C · Market-data poll (parallel loop)

main.pollPrices, 2-second ticker

  1. Ticker fires; Executor.GetSpotPrice, then GetReserves, then GetTotalFees — three sequential eth_call round-trips.
  2. MemoryStore.RecordPrice → candle / TWAP / volatility update.
  3. LPMetrics.UpdateState → impermanent loss, fees earned, net PnL.
  4. ImpactCurve.UpdateReserves → 50-point slippage curve.
  5. server.BroadcastPrice / BroadcastLPMetrics → WS → PriceChart / TWAPChart / LPStats / ImpactCurve.

D · Deploy / reseed

Fresh pool for a new demo

  1. scripts/deploy.sh runs forge script Deploy.s.sol --broadcast against Anvil.
  2. Foundry writes broadcast/Deploy.s.sol/31337/run-latest.json.
  3. On backend startup, config.LoadAddressesFromBroadcast reads that file.
  4. Backend verifies the pool exists and is seeded before accepting sessions.

Concurrency model

One errgroup in main coordinates {price-poll, HTTP server, shutdown watcher}. A second errgroup in Orchestrator owns the ~21 bot goroutines, all tied to the session context. Graceful shutdown on SIGINT/SIGTERM: stop session → 500 ms bot drain → 5 s server shutdown timeout. This satisfies the AGENTS.md "no orphaned workers" rule.

Deep Analysis

Findings from the structural pass (no dynamic profiling). Confidence: verified confirmed from code/tests/runs · supported strong code evidence, not measured · unverified plausible, needs profiling.

Verified facts & coupling

verified Inverted store ↔ engine dependency

store imports engine (stores engine.Trade); engine never imports store. The write path is closed by a closure in main.go. Confirmed by grep of imports and main.go:163-208. Consequence: main.go carries ~120 LOC of business logic that arguably belongs in a package.

verified store ↔ metrics cycle broken by interface

MemoryStore implements metrics.PriceDataStore (GetCandles/GetTWAP/GetVolatility); metrics.NewPriceProvider(memStore) gives bots a read-only view. Idiomatic Go cycle-break. Confirmed via store/memory.go doc comment + main.go:135.

verified Frontend/backend wire contract is hand-synced

frontend/src/types/index.ts mirrors Go JSON tags; AGENTS.md explicitly instructs updating both together. No codegen or schema.

verified go-ethereum dominates the dependency surface

backend/go.mod has 4 direct requires but pulls ~35 indirect modules (gnark-crypto, blst, c-kzg, otel, gopsutil, and notably a ProjectZKM/Ziren zkVM runtime). Build/CI cost and supply-chain surface are dominated by go-ethereum, not project code.

verified Both test suites pass

go test ./...: PASS (chain 2.57s, config 1.40s, engine 3.90s, metrics 3.43s, server 1.18s). forge test: 22/22 PASS (~40 ms). bots, store, contracts, cmd, and the frontend have no tests.

Supported hypotheses

supported H2 — Collapse the dual AMM ABI representation

executor.go hand-packs calldata (packSwapETHForApples, …) while internal/contracts/apple_amm.go holds generated bindings for the same functions. Switching Executor to the bindings (or deleting the unused ones) removes a silent drift class and ~100+ LOC of manual abi.Arguments packing. Verify which is on the call path first — packSwap* appears to be; bindings may be dead code.

supported H3 — Unbounded in-memory history growth

MemoryStore's doc comment references "unbounded price history and trade blotter arrays." Fine for a 2–3 minute demo, but the always-on staging instance (there is a start-staging-anvil.sh and a staging WS tunnel) will grow without bound. Add a ring buffer / retention cap on trades, events, and candle history. Low effort; prevents slow OOM.

supported H6 — main.go carries package-worthy logic

The OnTrade closure (event-severity thresholds, trade-flow gating, key-event construction) and the pollPrices price-move classifier are ~200 LOC of business rules in package main, untestable without a full wiring harness. Extracting internal/events (or internal/pipeline) would enable H1-style testing and shrink main to pure composition.

supported config is a deliberate hub with cross-language drift risk

internal/config is imported by engine, bots, server, store, and cmd; its Anvil addresses are independently re-derived by Deploy.s.sol and displayed by the frontend. Imports are verified; the drift risk (no compiler catches Go↔Solidity divergence) is an inference.

supported Server God-object

server.Server holds router, session, store, executor, WS client set, broadcast channel, and several mutexes; it is passed into the OnTrade closure and the poll loop. Central chokepoint, but keeps fan-out logic in one place. Supported by the server.go struct definition.

supported H1 — Bot strategy logic is the highest-value place to add tests verified gap

The zero-test state of internal/bots/ is verified; the recommendation is the hypothesis. It holds the demo's core behavior (whale impact sizing, retail frequency, MeanRev z-score triggers with three tuned half-lives). AGENTS.md demands "deterministic enough for repeatable demos" — seam the RNG (RandomDelay/RandomSize in base.go) behind an interface and table-test the MeanRev trigger boundaries. Low effort, directly de-risks the demo narrative.

Unverified hypotheses

unverified H4 — Price-poll does 3 sequential RPC round-trips every 2s

pollPrices calls GetSpotPrice, then GetReserves, then GetTotalFees serially each tick (main.go:458-532); GetSpotPrice is derivable from reserves. Collapsing to one getReserves + getTotalFees call (or a multicall) roughly halves poll-loop RPC traffic. Negligible against local Anvil; matters only against a remote RPC. Needs measurement.

unverified H5 — WebSocket broadcast fan-out under many clients

server.Server has a single broadcast chan interface{} with "channel full" drop logging and a lastBroadcastDropLog rate limiter — implying observed backpressure. Each trade triggers up to 3 separate broadcasts. Coalescing per-tick state into one framed message would cut serialization and lock contention. Profile with N simulated WS clients before investing.

unverified H7 — go-ethereum dominates build/dependency surface (fix is unverified)

The dependency fact is verified (see above); whether a lighter RPC client (ethclient alone, or a minimal JSON-RPC wrapper — the project already hand-packs ABIs) could drop most of the ~35-module transitive tree is not. High effort, meaningful CI-time and supply-chain payoff; verify feature usage first.

// main.go — the closure that inverts store → engine and hosts ~120 LOC of rules
executor.OnTrade(func(t *engine.Trade) {
    memStore.RecordTrade(t)
    memStore.RecordTradeFlow(t)           // feeds MeanRev EWMA z-score
    if sev := classify(t); sev >= EventLarge {
        memStore.RecordEvent(newKeyEvent(t, sev))
        srv.BroadcastEvent(t)
    }
    srv.BroadcastTrade(t)
    srv.BroadcastAccountUpdate(t.From)
})
