CRITICAL EXECUTION PATHS
────────────────────────────────────────────────────────────────────────────────
 A. Session start
    SPA SessionControls ► POST /session/start ► handlers.handleSessionStart
    ► Session.Start(duration) ► Orchestrator.Start(ctx) ► errgroup: bot.Run(ctx)
    ► state broadcast (WS) ◄ SPA re-renders

 B. Bot / user trade → UI
    bot.Run loop (or POST /trade/{buy,sell})
    ► Executor.SwapETHForApples / SwapApplesForETH
    ► NonceManager.Next ► sign tx ► Anvil eth_sendRawTransaction
    ► parse LogSwap / constant-product math ► Trade struct
    ► OnTrade callback (main.go): MemoryStore.RecordTrade
       + RecordTradeFlow (feeds MeanRev EWMA) + RecordEvent (large trades)
    ► server.BroadcastTrade / BroadcastEvent / BroadcastAccountUpdate
    ► WS /stream ◄ SPA Blotter / KeyEvents / AccountMetrics update

 C. Market-data poll
    main.pollPrices ticker(2s) ► Executor.GetSpotPrice / GetReserves / GetTotalFees
    ► MemoryStore.RecordPrice (candles/TWAP/vol) + LPMetrics.UpdateState (IL/fees/PnL)
    + ImpactCurve.UpdateReserves
    ► server.BroadcastPrice / BroadcastLPMetrics
    ► WS /stream ◄ SPA PriceChart / TWAPChart / LPStats / ImpactCurve

 D. Deploy / reseed
    scripts/deploy.sh ► forge script Deploy.s.sol --broadcast ► Anvil
    ► broadcast/Deploy.s.sol/31337/run-latest.json
    ► config.LoadAddressesFromBroadcast ◄ backend startup verification


KEY RELATIONSHIPS / COUPLING NOTES
────────────────────────────────────────────────────────────────────────────────
 * config.Accounts is the single roster shared by Deploy.s.sol (addresses),
   main.go (bot creation), Executor (signing), handlers (/accounts), and the
   frontend AccountMetrics view.
 * store ─► engine import: MemoryStore stores engine.Trade values. engine does
   NOT import store; the OnTrade callback in main.go inverts the dependency.
 * metrics ◄─ store via metrics.PriceDataStore interface (implemented by
   MemoryStore) to break the store↔metrics cycle; bots get a PriceProvider view.
 * Contract ABI is hand-packed in executor.go AND available as generated
   bindings in internal/contracts — two representations of the same interface.
 * Frontend types/index.ts must be kept in sync with Go JSON tags by hand.
 * No database, auth, or queue — all state is in-memory and reset per session.
